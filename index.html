R1 · mairie

GLPI : inventaire du parc et agent déployé par GPO

Recenser tout le parc de la mairie, puis automatiser sa remontée dans GLPI. Le passage du serveur en HTTPS a cassé le déploiement : il a fallu trouver pourquoi.

Cadre
Stage
Organisation
Mairie de Saint-Clément-de-Rivière
Période
Mars 2026
Résultat
Agent sur tout le parc, remontée en HTTPS
OutilsGLPI · Debian 13 · MariaDB · SSH · Active Directory · GPO · script batch
RéférentielC1C2C5
01Contexte02L'inventaire03Mise en place04Incident : plus rien ne remonte après le passage en HTTPS05Résultat06Preuves

01Contexte

Avant de pouvoir dépanner vite ou planifier un renouvellement, il faut savoir ce qui existe. J'ai d'abord fait l'inventaire manuel complet du parc pendant la semaine du 9 au 13 mars, puis il fallait automatiser la remontée des postes dans GLPI.

02L'inventaire

  • Postes Dell et Acer : système (Windows 10 22H2, Windows 11 24H2 et 25H2), mémoire, stockage, adresse IP.
  • Agents de prise en main à distance (TeamViewer, AnyDesk) et VPN présents sur chaque poste.
  • Tri du local technique et du câblage, sortie des postes obsolètes.

03Mise en place

Serveur GLPI sur une VM Debian 13 avec MariaDB, administré en SSH. L'agent GLPI est déployé sur les postes Windows par stratégie de groupe Active Directory.

04Incident : plus rien ne remonte après le passage en HTTPS

Constat
SymptômePlus aucun poste ne remonte dans GLPI une fois le serveur sécurisé sur le port 443.
Cause 1Les postes gardaient l'ancienne URL HTTP dans leur base de registre.
Cause 2L'agent refusait le certificat auto-signé du serveur.
  1. Réécrire le script batch : mise à jour forcée de la clé HKLM\SOFTWARE\GLPI-Agent, redémarrage du service, installation MSI silencieuse.
  2. Diffuser le certificat racine du serveur Debian dans le magasin des autorités de certification des postes, par GPO.

05Résultat

L'inventaire remonte automatiquement en HTTPS, sans intervention sur les postes.

06Preuves

à ajouter
  • Capture de la liste des ordinateurs dans GLPI (noms d'agents masqués).
  • Capture de la GPO de déploiement.
  • Le script batch corrigé.

01Contexte

Les collectivités sont des cibles fréquentes des rançongiciels, c'est aussi mon sujet de veille. La mairie voulait des règles simples pour les agents et une protection fiable sur tous les postes.

02Audit de la console EPDR

  1. Analyser les exports CSV de la console de protection des postes.
  2. Purger les doublons et les postes retirés du parc.
  3. Relancer les agents inactifs pour que chaque poste soit réellement protégé.

03Fiches de sensibilisation

  • Repérer un hameçonnage : vérifier la vraie adresse de l'expéditeur et la vraie URL du lien.
  • Mots de passe de 12 caractères minimum.
  • Aucune clé USB d'origine inconnue.

04Protocole rançongiciel

Débrancher le câble réseau, sans éteindre le poste. On coupe la propagation tout en gardant les preuves présentes en mémoire vive, utiles pour l'analyse.

05Preuves

à ajouter
  • Les fiches diffusées aux agents (PDF).
  • Le protocole rançongiciel.
  • Le bilan de l'audit EPDR : nombre de postes avant et après nettoyage.

R6 · mairie

Stockage réseau des vidéos des caméras piétons

Les vidéos des caméras piétons de la Police municipale étaient stockées sur un simple PC Windows. Objectif : les déplacer vers un vrai serveur de stockage, avec un transfert automatique et une documentation complète.

Pour
Police municipale
Organisation
Mairie de Saint-Clément-de-Rivière
Serveur
IBM System x3300 M4, Debian 12
Résultat
Transfert automatique vers le serveur
OutilsDebian 12 · dpkg · OpenSSH · clés SSH · script .bat · tâche planifiée Windows · IMM2
RéférentielC1C2C4C5
01Contexte02Accéder au serveur03Installer SSH sans Internet04Automatiser le transfert05Documenter06Ce que j'en retiens07Preuves

01Contexte

Les images des caméras piétons sont des données sensibles : elles doivent être conservées sur un équipement fiable, dans une arborescence claire, et rester accessibles uniquement aux personnes autorisées. Le stockage sur un PC de bureau n'offrait aucune de ces garanties.

02Accéder au serveur

Premier blocage : impossible de trouver l'adresse IP du système sur le port LINK 1, et aucun écran disponible pour le serveur. Un accès physique temporaire a permis de voir ce qui tournait : Debian 12, installé en netinst et sans accès à Internet.

03Installer SSH sans Internet

Le paquet openssh-server n'était pas installé, et l'image netinst ne le contenait pas. Plusieurs obstacles se sont enchaînés :

ObstacleCe qui se passaitSolution
Clé USBMauvais périphérique identifiéRepérer le bon disque avant de monter la clé
apt-cdromL'image netinst ne fournit pas le paquetAbandonner la piste du support d'installation
apt updateIncompatible avec une source cdrom:Installer les paquets à la main

La solution : télécharger les paquets .deb sur packages.debian.org depuis un PC connecté, les copier sur clé USB et les installer directement.

sur le serveurDebian
# repérer la clé USB, puis la monter
lsblk
mount /dev/sdX1 /mnt

# installer les paquets copiés depuis packages.debian.org
dpkg -i /mnt/*.deb

# démarrer SSH maintenant et à chaque démarrage
systemctl enable --now ssh

04Automatiser le transfert

  • Connexion au serveur par clé SSH, sans mot de passe.
  • Un script .bat transfère automatiquement les vidéos du PC vers le serveur.
  • Une tâche planifiée Windows lance le script sans intervention des agents.
  • Une structure de dossiers définie pour ranger les vidéos sur le serveur.

05Documenter

J'ai rédigé un rapport d'intervention complet : contexte, topologie, travaux réalisés, difficultés et résolutions, procédure pour les agents, tests de validation et recommandations.

Les identifiants (interface de gestion IMM2 du serveur et compte de service) sont dans un document séparé, stocké de façon sécurisée, avec la procédure pour réinitialiser le mot de passe du compte de service. Le rapport n'en contient aucun.

06Ce que j'en retiens

  • Sans écran ni réseau, il faut un plan pour accéder physiquement à la machine.
  • Sur un serveur hors ligne, on prépare les paquets à l'avance depuis un poste connecté.
  • Les identifiants ne vont jamais dans la documentation : un document à part, protégé, et un mot de passe à changer après l'intervention.

07Preuves

à ajouter
  • Le rapport d'intervention, dans sa version sans identifiants.
  • Une capture de la session SSH sur le serveur.
  • La structure des dossiers et la tâche planifiée (captures).
  • Le schéma de la topologie.

03Isoler le Wi-Fi invité

01Ce que j'ai observé et compris

01Ce que j'ai observé et compris

  • Tables MAC et ARP : un switch apprend les adresses sources ; un PC émet d'abord une requête ARP en broadcast avant tout ICMP.
  • Passerelle par défaut : indispensable pour sortir du réseau local.
  • MTU et TTL : le TTL baisse de 1 à chaque routeur ; avec une MTU de 200 octets, un paquet de 300 est fragmenté (bit « More Fragments »).
  • Spanning Tree : un port bloqué écoute toujours les BPDU ; reconvergence de 30 à 50 s ; spanning-tree portfast pour les postes.
  • RIP contre statique : RIP retrouve seul un chemin de secours après une coupure.
  • IPv6 : autoconfiguration, NDP remplace ARP (adresse multicast solicited-node, MAC en 33:33), pas de fragmentation par les routeurs.

01Fonctionnement

Le script reçoit une liste de dossiers, crée un répertoire daté /tmp/sav_JJMMAAAA, archive chaque dossier avec tar et fait jusqu'à trois tentatives. Il écrit les succès dans reussi.log, les erreurs dans erreur.log, et affiche un bilan.

02Le cœur du script

sauvegarde.shBash
for argument in $*; do
  if [ -d $argument ]; then
    essai=1; fini=0
    while [ $essai -le 3 ] && [ $fini -eq 0 ]; do
      tar -cf $rep/$(basename $argument).tar $argument 2>> $rep/erreur.log
      if [ $? -eq 0 ]; then
        echo "$(date) : $argument" >> $rep/reussi.log
        compteur_ok=$((compteur_ok + 1)); fini=1
      else
        essai=$((essai + 1))
      fi
    done
  fi
done

# Génère un mot de passe temporaire et affiche les étapes à transmettre à l'utilisateur.
Function New-TempPassword {
    param([int]$length = 12)
    $chars = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789!@#"
    -join ((1..$length) | ForEach-Object { $chars[(Get-Random -Maximum $chars.Length)] })
}
$pw = New-TempPassword -length 12
Write-Output "Mot de passe temporaire : $pw"
Write-Output ""
Write-Output "Procédure à envoyer à l'utilisateur :"
Write-Output "1) Se connecter avec le mot de passe temporaire."
Write-Output "2) Aller dans Paramètres > Compte > Modifier le mot de passe."

Veille

La cybersécurité des collectivités territoriales

Je l'ai choisi parce que c'est le quotidien de mon alternance. Les communes sont des cibles régulières des rançongiciels. Elles gèrent des données sensibles (état civil, urbanisme, familles) avec peu de moyens. Je suis les attaques qui les visent et ce qu'une petite collectivité peut faire concrètement.

  • Rançongiciels et hameçonnage dans le secteur public.
  • Dispositifs d'aide de l'État pour les collectivités.
  • Mesures accessibles : sauvegardes hors ligne, double authentification, mises à jour, sensibilisation.
  • Cadre réglementaire : RGPD et directive européenne NIS 2.

Ce que j'en retiens se retrouve directement dans mes fiches pour les agents (R3).
